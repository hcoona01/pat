# PROJECT RULES: VAULT

Every contributor, agent, and future development task MUST strictly adhere to these rules:

1. **Originality & Code Provenance**
   - Do NOT copy code from existing distributed object storage systems (including but not limited to MinIO, OpenStack Swift, Ceph, SeaweedFS, Garage, Tahoe-LAFS).
   - Write all logic, coordination protocols, and data structures from scratch using standard, permissible open-source Python libraries.
   - Record every third-party dependency, its exact purpose, and its license in `README.md`.

2. **No Fabrication of Evidence**
   - NEVER fabricate test results, benchmarks, logs, metrics, screenshots, or performance claims.
   - All evidence recorded in `docs/evidence.md` or `docs/generated-evidence/` must be generated by actual, reproducible test executions.
   - If a test fails or a scenario exposes a bug or edge case, report it truthfully.

3. **Definition of Done**
   - Only mark a requirement or feature as complete when:
     a) Real, executable code is written.
     b) Automated unit or integration tests exist and pass.
     c) Observable evidence (logs, test outputs, or metrics) validates the behavior.
   - Stubs, mock-only implementations, or TODO placeholders do not constitute completion.

4. **Prototype Reality & Honest Limitations**
   - Vault is a hackathon-grade prototype designed to demonstrate distributed systems principles (Raft metadata consensus, rendezvous placement, quorum writes, bitrot detection, Reed–Solomon erasure coding, dynamic rebalancing).
   - It is NOT production-ready storage.
   - Maintain and continuously update `docs/limitations.md` with an honest accounting of trade-offs, single points of failure, scaling boundaries, and prototype assumptions.

5. **Approved Technology Stack**
   - Language: Python 3.12+
   - API Framework: FastAPI + Uvicorn
   - Networking & Async: `asyncio`, `httpx` (async client with connection pooling & timeouts)
   - Configuration & Data Models: Pydantic v2 + Pydantic Settings
   - Node Local State: SQLite via `aiosqlite` with WAL mode
   - Consensus Layer: Python Raft / Replicated State Machine (e.g., `PySyncObj`)
   - Erasure Coding: Maintained Reed–Solomon library (e.g., `zfec` or Galois field arithmetic)
   - Cluster Orchestration: Docker Compose
   - Testing & Metrics: `pytest`, `pytest-asyncio`, Prometheus `/metrics` exposition (`prometheus-client`), structured JSON logging, SHA-256 cryptographic hashing, Rendezvous (Highest Random Weight) hashing.

6. **Preservation of Documentation**
   - Preserve all documentation integrity and keep design documents synchronized with actual code changes.
